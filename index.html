Abstract

A forecasting model knows how unsure it is. The step that decides how much to bet almost never asks.

Most machine-learning trading pipelines run in two decoupled stages: a model predicts returns, then a heuristic — top-k, equal weight, a fixed volatility target — turns those predictions into positions. The model’s own uncertainty is discarded at exactly the moment it would be most useful.

CAST closes that loop. A cross-asset collaborative Kalman filter estimates each stock’s latent state online, coupling thirty names through a correlation matrix fitted before 2010 and fusing three integrated-random-walk orders by online Bayesian model averaging. A model predictive controller then turns those forecasts into positions, and the uncertainty it is charged for is built from the same fused weights that produced the forecast. Position size therefore shrinks exactly when the filter is least sure, and drawdown control becomes the objective the system optimises rather than a metric reported afterwards.

The system is training-free and gradient-free: no neural network, no gradients, CPU only. We evaluate on four panels of thirty daily-close stocks — NASDAQ, CSI 300, TPX100 and a cross-currency basket — over fifteen unbroken years, with the filter parameters calibrated on pre-2010 data and never refitted.

Method

Architecture diagram
The CoKF → MPC loop, with σ drawn as the feedback limb.

EstimatorCoKF

A cross-asset collaborative Kalman filter estimates each stock’s latent state online. Thirty stocks share one joint state, coupled through a correlation matrix fitted before 2010, so a move in one name corrects the estimates of the others.

Three integrated-random-walk orders — level, trend, curvature — run in parallel as competing hypotheses about how smooth a trend is. Their weights are re-estimated every day, per stock, by online Bayesian model averaging over how well each predicted the last seven days.

ControllerMPC

A model predictive controller plans seven days ahead, solves a linear program each day, and executes only the first move before re-planning tomorrow with new information.

The uncertainty curve it is charged for is built from the same fused model-order weights that produced the forecast — one object, two uses. That is the loop, and it is why position size shrinks exactly when the filter is least sure.

maximise   Σl [ Δpl · ul  −  λ · σl · |ul| ]
subject to   Σl ul = −u0 ,   |ul| ≤ β · V / pl
  • Δp_lpredicted price change l days out, from the filter
  • σ_lhow unsure the filter is about day l — from the same fused model, and it grows with l
  • λ·σ_l·|u_l|a toll on every share traded, priced by the model’s own uncertainty
  • Σ u_l = −u_0the plan must return to flat — no runaway accumulation
  • β = 0.5largest single move allowed, as a fraction of that stock’s equity
